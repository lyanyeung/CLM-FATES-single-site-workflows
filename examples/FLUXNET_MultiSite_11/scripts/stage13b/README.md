# Stage 13b — Corrected eleven-site dated BIF heights (read-only)

**Purpose**: Follow the eight-site dynamic ZBOT method in `examples/FLUXNET_MultiSite_8/scripts/07_make_eight_site_datm_timevarying_zbot.py`, but fix a real issue found in the eleven-site Stage13 audit: `VAR_INFO_DATE` is sometimes `YYYYMMDD` rather than `YYYYMMDDHHMM`. Some WS height values are blank. The old report therefore mistakenly showed zero TA/WS entries for FR-Fon, FI-Sod, CH-Aws and CH-Fru. This is an audit fix, NOT approval of early height assumptions.

## What stays the same as the eight-site workflow

- Generate `ZBOT(time)` from **dated BIF `TA_F` measurement height**; do not set an unchanging global value for all stations/years.
- Inspect `WS_F` height separately; report material TA/WS discrepancies, **do not silently rescale WIND**.
- Before the earliest BIF `TA_F` height date, **do not fill the missing historical height unless a specifically documented scientific decision allows earliest-height backfill**. The eight-site `--allow-early-extrapolation` flag was an explicit disclosure, not evidence that backfilling any multi-decade gap is scientifically correct.
- No automatic reuse of eight-site lat/lon coordinates, source paths, or `processed_v5` outputs. The eleven-site selected source tags are different (`v07a`, `pressure07a`, `pressurelw08a`, `landrh11a`).

## Interpret user-observed anomalies correctly

- `20191028` means date-only; we parse as midnight for comparison and mark `DATE_ONLY_MIDNIGHT_ASSUMED`. We cannot independently infer a true instrument-change time finer than day.
- CH-Aws `WS_F` blank height remains an explicit missing-height entry. Never invent a WS height; it is *not* required to calculate TA-based ZBOT but wind-height consistency remains unresolved.
- BE-Bra's TA 32.2 m from 2016-12-19 and WS 39.2 m from 2020-04-10 overlap only from April 2020. Previous Stage13 counted a 7 m mismatch during the entire record by *extrapolating both heights backwards* for diagnostic purposes, misleadingly calling the whole series observed mismatch. Corrected audit counts only their **documented overlap**.
- GL-ZaH, IT-Noe, FI-Sod and FR-Fon have lengthy pre-BIF forcing intervals. The first later instrument height is **not evidence that the sensor was always at that height historically**. Search older FLX/EUF metadata and tower documentation if possible before approving any long early backfill.

## Gate before DATM

1. Verify BIF date parsing and inspect `03_manual_review_issues.csv`.
2. Resolve `TA_F` missing historical coverage using older metadata or a justified, annotated earliest-height assumption. Record decisions in `06_manual_height_policy_DECISIONS_TO_EDIT.csv`.
3. Perform full science QC of temperature, radiation, precipitation, wind and source transitions, and surface/PFT footprint review. The eleven candidate CSVs passed basic numeric audit, *not* scientific approval.
4. Only then adapt the eight-site annual NetCDF writer for all eleven, reading correct site-selected candidate versions, applying approved dynamic ZBOT choices and independently auditing `NO_LEAP` time/units/fields. No DATM or spin-up is generated by these Stage13b scripts.
