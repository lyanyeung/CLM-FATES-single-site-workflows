# Stage05BM: Tmd QC0 controls, not event truth

Status: implementation and synthetic tests only; no real 05BM CDS results have yet been run or observed. All 45 candidate values remain on scientific HOLD. No replacements are approved.

The actual Stage05BL run found broad-range-screened QC0 measurements within 30 days for only two of the 17 groups: Tmd TA (1,375 samples) and Tmd LW_IN (69). The closest are 33 and 686 hours after the respective 2005 event group ends. This does not establish the absence of measurements outside the tested inputs or windows. The other 15 groups have no qualifying samples in this particular scan. See `STAGE05BL_ACTUAL_FIVE_SITE_30DAY_QC0_RESULTS.md`.

## Prespecified control design

The script hash-checks the exact real Stage05BL samples, Stage05BF selected ledger, Stage05AZ group summary and the reused Stage05AZ reference parser, then selects at most three NEW UTC days without looking at measured values or errors. These are TA after 24 hours and within seven days, TA after seven days through the end of the 30-day sample window, and LW_IN after seven days through the end of its 30-day sample window. For each category choose the day with most eligible half-hours (earliest on ties), requiring at least 16 TA or four LW_IN half-hours. Four hours is not implied: four half-hours are a weak minimum and small samples must be interpreted accordingly. All four diagnostic clock offsets must have reference support inside the same requested UTC day. If any category lacks sufficient support, the script stops before submitting requests.

One ERA5-Land time-series request per distinct selected UTC day, at most three, provides new control-day data. Already completed event-day comparisons are not repeated. CSV ZIP, CRC, variables, 24 UTC hours, coordinates and physical range are validated using the hash-pinned Stage05AZ parser. The event-period same-release QC2-minus-grid medians are held fixed for the respective clock hypotheses and added to each control-day grid value; the resulting predictions are compared with original QC0 values at those other times. This tests transferability to these restricted controls, not the true event-time value. UTC+9 is a diagnostic base assumption; UTC+8:30, UTC+9:30 and longitude-derived local mean solar time are sensitivity cases, not a probability distribution or a resolution of the publisher clock conflict.

The CDS time-series product lists downwelling thermal radiation as de-accumulated hourly J/m²; division by 3600 provides the hourly mean W/m². Stage05AZ assumes constant flux within each hour when matching half-hours; temperature is interpolated to the midpoint. These are approximations. See the [ECMWF product guide](https://confluence.ecmwf.int/pages/viewpage.action?pageId=576394633).

Output contains paired controls, per-day/variable/clock descriptive error summaries, request metadata and SHA-256 hashes. Consecutive samples are autocorrelated; neither the descriptive p95 nor the clock range is a confidence interval. The controls do not validate any PA group or the other sites or prove an acceptable error threshold. Grid/site representativeness, different measurement heights, model dependence, changed weather/season and unresolved time conventions limit interpretation. Additional evidence and explicit approval remain necessary before any production replacement.

By default the program runs a preflight without network or output creation. `--submit` explicitly requests CDS data and writes only a new diagnostic directory under `~/japanflux_stage05bm/`. It never changes original ZIPs, production forcing, PFT, soil, model cases or Slurm. A failure retains any already downloaded diagnostic files and stops; it does not approve a value.
