# Stage05AY: native-window diagnostics and shadow screens

**Implementation and synthetic tests only. No actual Stage05AY IRIDIS6 run is claimed. All 45 fields remain SCIENCE HOLD; approved replacements: 0.** Existing real Stage05AW/AX results are documented in the handoff and actual reports.

## What is known and what is not

The recorded five-site audit found 45 selected F=ERA QC2 fields at 35 site/native half-hours outside the previously defined independent ERA5-Land hourly envelopes. The independent evidence includes 22 earlier strong-context and 23 context-only fields; Tef/Tmd use an unverified operator JST+9 hypothesis despite their source README saying local solar time. All 45 lack a two-sided QC0 anchor within ±24 h. A QC2 provenance run describes the selected product source, not a duration of abnormal meteorology. The 45/35 scope is not a count of independent events.

The true anomaly boundaries, validity of plausible QC2 neighbors, cross-variable consistency, original publisher clock, and common cause remain unresolved. For example, Tmd's documented 2011 and 2022 PA sequences near 49, 0, 49 kPa are compatible with an interpolation involving a bad zero, but that is only a **hypothesis**: neither the faulty precursor nor the interpolation pipeline has been observed. Similar native dates alone cannot distinguish common upstream data, processing, independent errors, or alignment artifacts. Compare shapes, units, signs, timestamps, boundary offsets, and F/ERA/MDS across sites; inspect product-generation and upstream evidence before assigning a cause. FLUXNET describes a general MDS and downscaled-ERA processing pipeline, but that documentation does not prove the exact JapanFlux release implementation or a particular failure: https://fluxnet.org/data/fluxnet2015-dataset/data-processing/ .

## Diagnostic definitions and limitations

The script re-reads the actual outer and nested original ZIPs one site at a time via the exact pinned Stage05AX helper, verifies the five outer ZIP SHA256s published in Stage00, verifies README against Stage05K, exhausts the HH member to exercise ZIP CRC, and verifies the flagged original source F/ERA/QC against the actual Stage05AW ledger. SHA256 is checked before and after each scan. It records input and source hashes, source columns and row counts. The AW ledger gate requires the documented populations and HOLD state. It does not verify independent ERA5-Land ZIPs again or repeat the 45 comparisons.

`native_windows.tsv` contains the original target-variable F, QC, same-release ERA, raw and MDS fields and co-timed PA/TA/LW_IN fields (when present), for up to ±48 half-hours around each flagged field. Presence flags distinguish a nonexistent column from a blank cell. Repeated rows from overlapping windows are expected. All timestamps are source-native START timestamps; original END is checked by Stage05AX at selected windows. No UTC conversion is applied. `native_date_clusters.tsv` is a preliminary native-date co-occurrence list, **not** a synchronized UTC or causal comparison. Tef/Tmd require clock sensitivity analysis.

The predefined broad screening intervals are PA 50–115 kPa, TA −70–65 °C, LW_IN 70–650 W m⁻², inherited from Stage05AX for comparability. They are diagnostic heuristics, not validated site-specific thresholds. An inside value is **not** certified normal; an outside value is a screen, not an automatic finding. A flagged value inside the interval has unresolved bounds. Consecutive outside-screen values in the available ±24 h window define the *observed screen run*. A missing timestamp, missing value or window edge censors its boundary; an inside-screen neighbor supplies only a provisional bound. A screen run can miss subtle bad points or include valid extremes, and is not the proven physical anomaly duration. Runs are reported per flag and may overlap. All results require human inspection of the exported windows, especially suspicious but within-range values.

The QC2 bridge is a **limited exploratory method screen** only. It is computed only when a screen run has at most four half-hours; all run cells belong to the existing reviewed 45; immediately adjacent cells are inside the broad screen, both selected QC2 and F≈same-release ERA; and no boundary is censored. Linear interpolation gives a shadow number with the exact label `QC2_SHADOW_BRIDGE_REVIEW_ONLY`: same-release ERA-derived continuity, not QC0, independent verification, an approved estimate or production forcing. Passing these coarse tests does not establish anchor plausibility, correct episode width, physical coherence, or uncertainty. Review neighboring tendencies and curvature, other available sensor/MDS flags, time-of-day, paired-variable behavior, and sensitivity to a wider interval; withhold the bridge if any are doubtful. The 4-HH cap is an explicit conservative operational choice, not a demonstrated scientific optimum. Rows outside the 45 are never given a shadow estimate.

An independent ERA5-Land assisted candidate is an alternative **design only**, not implemented or calculated here: verify original CDS files against their saved hashes and provenance; establish station time and UTC offset sensitivity, distinguish instantaneous t2m/sp from hourly accumulated radiation; compare matched valid time and exact interval overlap including midnight; assess grid elevation, station height and representativeness; fit any bias correction using independent clean samples outside the event, with temporal block holdout and sufficient coverage, not the suspected QC2 segment itself. Quantify error against withheld measured QC0, compare against the bridge and uncorrected reference, test season/time-of-day and choice of interval, and explicitly report uncertainty. Hourly grid data cannot identify unique 30-minute tower values. Tef/Tmd require publisher confirmation or explicit unresolved-clock sensitivity results. The ERA5-Land **hourly time-series** product de-accumulates `strd`; convert J m⁻² to hourly mean W m⁻² by /3600, do not difference it again. Other ERA5-Land products have different accumulation conventions; verify the exact product and metadata: https://confluence.ecmwf.int/pages/viewpage.action?pageId=627854124 and https://confluence.ecmwf.int/spaces/CKB/pages/140385202/ERA5-Land%2Bdata%2Bdocumentation . A half-hour interval [t,t+30min) must be matched against the correct hour-ending interval, including 00 UTC rollover; do not silently treat instantaneous temperature or pressure as accumulated radiation.

Manual review should also compare PA with station elevation and pressure context, TA with neighboring temperatures and humidity where available, and LW with temperature/cloud/radiation context. Plausibility ranges alone are not a coupled physical test. The exported fields support that review; the script does **not** implement a complete thermodynamic model, original-publisher time proof, ERA5-Land bias validation, or all possible physical outlier detection.

## Approval gate and safety

No value may be applied without a separate scientifically documented decision: original-release and independent-reference provenance, source-clock resolution or defensible sensitivity, boundary and neighboring-quality review, cross-variable checks, held-out evaluation/uncertainty, a per-field approved scope, and explicit user approval. The code has no write path to source ZIPs or forcing and creates only a fresh direct child of `~/japanflux_stage05ay`; it does not touch PFT, cases, Slurm or AD400, submit jobs, or use the network. It does not build a full shadow forcing file, so non-event forcing identity is not claimed or tested. Compare all non-event cells exactly in a future separately approved shadow-forcing stage.

Output files: `events_HOLD.tsv` (45 individual screens, boundary values and conditional shadow values), `native_windows.tsv` (source evidence), `native_date_clusters.tsv` (co-occurrence), and `summary_HOLD.json` (scope, counts, hashes and limitations). Failures must be investigated rather than bypassing gates. Synthetic tests cover screen bounds, missingness/censoring, QC2/F=ERA anchors, unreviewed outlier exclusion, long runs, year boundary and pinned helper/manifest. They do not replace a real IRIDIS6 run.
